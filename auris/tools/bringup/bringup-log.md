## Missing sensor feeds

The head stream is not present in `/state` (`head.fresh` is false and Euler angles are null). The active service explicitly uses `--head-source none`, so it does not attempt to read the head device. The installed CLI documents `--head-source i2c` as an MPU6050 on Pi I²C bus 1 at `0x68` by default, and `--head-source serial` as `H1` samples from the ESP-NOW bridge. Neither path should be selected until the attached sensor and its data path are identified.

The Pi enumerates one CP2102 USB serial interface at `/dev/ttyUSB0`; it does not enumerate a `/dev/ttyACM*` device. I²C bus 1 reports one responder at `0x2d`; this does not identify an MPU6050 at `0x68` (or `0x69` if AD0 is high), so the head part remains unknown. Buses 13 and 14 had no responders.

The active Pi service runs at 115200 baud and currently produces pointer data, while the installed CLI documents 460800 baud for the P1/H1 bridge stream. The existing pointer USB table works at the current setting. Keep it unchanged until the bridge is confirmed to emit P1/H1; changing only the Pi baud would break the working pointer feed.

The service currently uses `--audio null`, so the dashboard is intentionally silent while head orientation and camera pose are missing.
