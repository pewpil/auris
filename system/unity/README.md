# Auris — Unity Audio Engine (dumb renderer)

Unity receives frozen `SceneState` datagrams from the Python pipeline and does
only one thing: place earcon sources at head-relative azimuth/elevation/distance
and render them binaurally. It never computes poses. The wire contract lives in
Python at `../python/auris/contracts/scene.py`; coordinate rules in
`../python/auris/contracts/conventions.md`.

## Repository layout

Only the source of truth is committed:

```
Assets/Auris/Scripts/
├── SceneStateDecoder.cs      byte-for-byte mirror of the Python SceneState v1 codec
├── SceneStateReceiver.cs     UDP listener (background thread → main-thread queue)
├── SpatialAudioManager.cs    earcon source pool, head-relative placement
└── BeaconMode.cs             stub — keyboard query arrives in Phase 2
```

The Unity project itself (`ProjectSettings/`, `Packages/`, `.csproj`, …) is
generated by the editor and git-ignored.

## One-time editor init (Unity 2022 LTS)

1. Unity Hub → **New project** → template **3D (Built-in)** or **URP**.
2. Location: this directory (`system/unity`) — the committed `Assets/` merges in;
   the editor generates the rest. Name it `AurisAudio`.
3. Open the scene, then wire the runtime objects:

| GameObject | Components | Notes |
|---|---|---|
| `HeadAnchor` | **Audio Listener** | the user's head; keep at scene origin for the synthetic demo |
| `SceneStateReceiver` | `SceneStateReceiver` | default port 5555 |
| `SpatialAudioManager` | `SpatialAudioManager` | assign `receiver` → SceneStateReceiver, `headAnchor` → HeadAnchor, `earcon` → any looping clip |

4. Press **Play** and run the Python side:

```bash
cd ../python
uv venv .venv && uv pip install --python .venv/bin/python numpy
.venv/bin/python -m auris stream --synthetic --port 5555
```

Three synthetic objects (bottle, mug, book) sit at varied heights; the bottle
orbits slowly and the whole soundscape yaws sinusoidally.

## Direction math (must match Python conventions)

Python sends head-relative angles (azimuth 0 = ahead, positive right;
elevation positive up). Unity local head space is +z forward, +x right, +y up,
so the source offset is `headAnchor.rotation * (sin az · cos el, sin el,
cos az · cos el) * distance` — implemented in
`SpatialAudioManager.AzimuthElevationToDirection`.

wire this hex into a Unity Test Framework test before trusting any decoder
change.

## Phase 2 bring-up (not yet wired)

- HRTF spatializer plugin: **3D Tune-In Toolkit** (primary) or **Steam Audio**
  (alternative); Project Settings → Audio → Spatializer Plugin, then keep
  `AudioSource.spatialize = true`.
- Earcon library per object class (bottle = bubbling, mug = chime, book = page
  rustle); distance cues (gain rolloff, low-pass, slight reverb).
- Beacon mode: periodic ~100 ms noise-burst pings for `snapshot.BeaconObjectId`;
  keyboard query first, speech later.
- Head coupling: rotate `HeadAnchor` from `snapshot.HeadRotation` once a
  Python→Unity world-frame mapping is fixed (Prototype demo may keep the anchor
  static since angles are already head-relative).
